title: "analysis"

Manage analyses.

## `create`

Create a root analysis for the configured code version.

```bash
bevor analysis create [OPTIONS]
```

| Parameter | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `--name` | text | No |  | Optional analysis name. |
| `--collision` | choice | No | surface | What Bevor should do if analysis already exists for the given code |
| `--yes` | boolean | No |  | Skip confirmation of action. |
| `--json` | boolean | No |  | JSON output |
| `--force` | boolean | No |  | Skip checks. Not recommended. |

## `use`

Update the configured analysis.

```bash
bevor analysis use [OPTIONS]
```

| Parameter | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `analysis_id` | text | Yes |  | Analysis container id. |

```bash

```

| Parameter | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `version_id` | text | Yes |  | Analysis version id to set as HEAD. |

## `list`

List analyses for the configured project, or use the --project flag to list for a specific project, or
pass the --all flag to list analyses across all projects in the configured team.

```bash
bevor analysis list [OPTIONS]
```

| Parameter | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `--page` | integer | No |  | Page number to use for resource that supports pagination |
| `--page-size` | integer | No |  | Page size to use for resource that supports pagination |
| `--order` | choice | No |  | How to order results when a resource supports pagination |
| `--order-by` | choice | No |  | What field to order results by when a resource supports pagination |
| `--project, -p` | text | No |  | Project ID (defaults to .bevor config). |
| `--user` | text | No |  | Analysis creator to filter by |
| `--is-owner` | boolean | No |  | Analysis filter by owner only |
| `--json` | boolean | No |  | JSON output |
| `--all` | boolean | No |  | List analyses for all projects in current team |

## `run`

Start a run of Bevor Security pipeline for the configured analysis head (or ``--version``).

```bash
bevor analysis run [OPTIONS]
```

| Parameter | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `--version` | text | No |  | Version id to run (default: configured analysis head). |
| `--no-wait` | boolean | No |  | Return immediately without waiting for the event stream to complete. |
| `--silent` | boolean | No |  | Suppress intermediate output logs. |

## `retry`

## `diff`

Show finding diffs for the configured analysis head (or ``--version``). --staged flag will show
the diff of the staged commits. Excluding it, it'll show the diff of committed findings between the analysis
and its parent.

```bash
bevor analysis diff [OPTIONS]
```

| Parameter | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `--version` | text | No |  | Version id to diff (default: configured analysis head). |
| `--staged` | boolean | No |  | Show staged drafts instead of version-vs-parent diffs. |
| `--json` | boolean | No |  | JSON output |

| Parameter | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `--version` | text | No |  | Version id to commit (default: configured analysis head). |

## `child`

Create a child analysis version using the configured code. If there is no currently configured
analysis (`bevor context` or `bevor analysis current`), you can pass a --version, or you can link an analysis
using `bevor analysis use`. Bevor will check whether an analysis
exists for the given code version or not, and early return if so. Use the --collision argument to bypass this,
but it's advised not to.

```bash
bevor analysis child [OPTIONS]
```

| Parameter | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `--version` | text | No |  | Parent version id (default: configured analysis head). |
| `--collision` | choice | No | surface | What Bevor should do if analysis already exists for the given code |

## `merge`

Merge one analysis into another. --from is required, but --to defaults to your active analysis's HEAD.
This will create a child analysis version of the --to, and update its HEAD.

```bash
bevor analysis merge [OPTIONS]
```

| Parameter | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `from_analysis` | text | No | --from | Source analysis container id. |
| `--to` | text | No |  | Destination analysis container id. |

## `findings`

List findings on the configured analysis, or ``--version``. Including a --sarif path will output
the findings into a SARIF format. --interactive will open an interactive terminal to explore further.

```bash
bevor analysis findings [OPTIONS]
```

| Parameter | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `--version` | text | No |  | Version id to list findings for (default: configured analysis head). |
| `--interactive` | boolean | No |  | Browse findings and expand the focused row. |
| `--json` | boolean | No |  | JSON output |
| `--sarif` | path | No |  | Write SARIF for the configured analysis to this path. |

## `remediations`

List remediated findings for the configured analysis head (or ``--version``). By default it'll list remediations
for your currently configured analysis, but you can override this with --version, or you can pass --project which will
list remediations across an entire project instead.

```bash
bevor analysis remediations [OPTIONS]
```

| Parameter | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `--page` | integer | No |  | Page number to use for resource that supports pagination |
| `--page-size` | integer | No |  | Page size to use for resource that supports pagination |
| `--order` | choice | No |  | How to order results when a resource supports pagination |
| `--order-by` | choice | No |  | What field to order results by when a resource supports pagination |
| `--project` | text | No |  | Project to filter by. Defaults to current configuration |
| `--version` | text | No |  | Version id (default: configured analysis head). |
| `--json` | boolean | No |  | JSON output |

## `delete`

Delete an analysis container or version.

### `full`

Delete the entire currently configured analysis container

```bash
bevor analysis delete full [OPTIONS]
```

### `version`

Delete a single analysis version (leaf).

```bash
bevor analysis delete version [OPTIONS]
```

| Parameter | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `version` | text | No |  | Version id to delete (default: configured analysis head). |
